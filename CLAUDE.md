# Правила для Claude в этом репозитории

Эти правила действуют всегда, во всех сессиях, независимо от текущего
permission mode. Если встал выбор — следовать этим правилам или
действовать «автономно» — всегда побеждают эти правила.

## Что делать только по прямой команде пользователя

- **Не запускать GitHub Actions workflow** (`gh workflow run`, `workflow_dispatch`
  через MCP, кнопка «Run workflow» в UI) без явной просьбы — «запусти сборку»,
  «собери APK», «run build» и т.п. Код коммить и пушить в main как обычно,
  но дорогая сборка (~45 минут Gradle, ~105 МБ артефакт) — только по просьбе.
- Не мёрджить PR.
- Не делать `git push --force` или `--force-with-lease` в main.
- Не удалять ветки, теги или релизы.
- Не создавать GitHub Release.
- Не менять видимость репозитория (public/private).

## Что можно делать свободно

- Писать и править код в `mod/`.
- Коммитить и пушить в текущую ветку (включая main — это личный репо).
- Клонировать и читать сторонние репозитории для контекста.
- Отменять свои собственные ранее запущенные сборки, если пользователь
  попросил или сборка стала не нужна.
- Планировать себе напоминания (`send_later`) для проверки статуса
  уже-запущенной сборки — но не для автоматического перезапуска.

## Стиль работы

- Если задача делится на несколько этапов, делать по одному этапу за заход
  (коммит + сборка только по просьбе), не копить изменения.
- Честно говорить, что реально работает, а что — заглушка «в разработке».
  Не выдавать «UI есть» за «фича работает», если за ней не стоит реального
  поведения в Telegram-Android.
